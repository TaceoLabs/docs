# Client SDK - OMap

The OMap client is the Merces client used on the Plasma, Stable, Polygon and Zenith deployments. It runs
entirely in your application: it generates proofs locally, holds the signing key, and talks
to the gateway, the ID registry and the MPC nodes on your behalf. Balances and amounts
never leave it in the clear.

It exposes two privacy modes and the yield vault, neither of which the Monad and Worldchain
client offers.

:::info Which client do I need?
Pick by deployment. **Plasma, Stable, Polygon and Zenith** use this client,
[`@taceo/merces2-client`](https://www.npmjs.com/package/@taceo/merces2-client). **Monad and
Worldchain** use [`@taceo/merces-client`](/docs/finance-solutions/integrate/client-sdk),
which has a different API. They are not interchangeable.
:::

:::warning Testnet
These deployments are testnets using test tokens with no real-world value. Never use
mainnet keys or real funds against them.

Note that - depending on the stability of your chosen RPC provider - you may have to add retries to various calls.
:::

## Endpoints and addresses

Three services sit in front of Merces on these deployments; the gateway is optional. Each
deployment has its own endpoints, following the pattern `<chain>.<service>.merces2.taceo.io`,
where `<chain>` is `plasma`, `stable`, `polygon` or `zenith`. For Plasma:

| Service | URL |
|---|---|
| ID registry | `https://plasma.id-registry.merces2.taceo.io` |
| Gateway | `wss://plasma.gateway.merces2.taceo.io` |
| Orchestrator | `https://plasma.orchestrator.merces2.taceo.io` |

The vault contract differs per deployment:

| Deployment | Vault |
|---|---|
| Plasma | `0x3D2B3bC89c8D07Bb46C755bd8fde7D4271cf40d7` |
| Stable | `0xE67b5933CA36273C17b7384a96bEBc2c340c9093` |
| Polygon Amoy | `0xCE0a243191CF99b10171be72CFF54318c700E63E` |
| Zenith | `0xE67b5933CA36273C17b7384a96bEBc2c340c9093` |

Node URLs and the Merces, ID registry and token contract addresses are on
[Deployments & status](/docs/start-here/deployments-and-status).

Note that the ID registry appears twice in a deployment's configuration, as two different
things: the service URL above, and the ID registry *contract* address on the Deployments
page. This client needs both.

## Requirements

Node.js 22 or later, a wallet funded on the chain you are targeting, the endpoints and vault
address above, and the Merces, ID registry and token contract addresses for that deployment.

The package is **ESM-only**. It has no CommonJS build, so it cannot be `require()`d — use
`import`, or a bundler that handles ESM.

## Install

```bash
npm install @taceo/merces2-client viem
```

The package bundles its own proving artifacts — the circuit wasm and the zkey ship inside
it — so there is nothing else to download before you can generate a proof.

## Create a client

```typescript
import { createWalletClient, createPublicClient, hexToBytes, http } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { Client, SK_DERIVE_MESSAGE, deriveSk } from '@taceo/merces2-client';

const account = privateKeyToAccount(process.env.PRIVATE_KEY as `0x${string}`);

const walletClient = createWalletClient({ account, chain, transport: http(RPC_URL) });
const publicClient = createPublicClient({ chain, transport: http(RPC_URL) });

// Any BabyJubJub secret key works; here it is derived from a wallet signature.
const signature = await walletClient.signMessage({ message: { raw: SK_DERIVE_MESSAGE } });
const secretKey = deriveSk(hexToBytes(signature));

const client = new Client({
  idRegistryUrl: ID_REGISTRY_URL,
  gatewayUrl:    GATEWAY_URL,
  nodeUrls: [NODE_0_URL, NODE_1_URL, NODE_2_URL],
  contractAddress: MERCES_ADDRESS,
  tokenAddress:    TOKEN_ADDRESS,
  vaultAddress:    VAULT_ADDRESS,
  token: 'EIP3009',
  walletClient,
  publicClient,
  secretKey,
});
```

:::warning
This requires you to pass your private key to the SDK. Use testing wallets or secure the key/environment variable in some manner.
:::

### The secret key

Every account has a BabyJubJub secret key. Its public key is registered against your address
and proofs prove ownership of it, so the client must always be given the same key for a given
address.

Deriving it from a wallet signature, as above, is deterministic — the same wallet always
produces the same key — so it does not need storing. If you hold the key elsewhere, pass it
as the `secretKey` bigint instead. Anyone with the key can spend the account's Merces balance.

### Configuration

| Option | Required | Notes |
|---|---|---|
| `idRegistryUrl` | Yes | Maps wallet addresses to their index in the tree |
| `gatewayUrl` | No | WebSocket endpoint that submits transactions and reports completion. Without it, the wallet sends every transaction directly to the contract — see [Without a gateway](#without-a-gateway) |
| `secretKey` | Yes | The account's BabyJubJub secret key, as a `bigint`. See [The secret key](#the-secret-key) |
| `nodeUrls` | Yes | The MPC nodes. Shares are encrypted to their public keys |
| `contractAddress` | Yes | The Merces contract on your chain |
| `tokenAddress` | Yes | The ERC-20 being wrapped |
| `vaultAddress` | Yes | Required even if you never use the vault |
| `token` | Yes | `'ERC20'` or `'EIP3009'`. `'ERC20'` works on every deployment, with or without a gateway. `'EIP3009'` makes deposits gasless and requires `gatewayUrl` |
| `gatewayTimeout` | No | Wait for the gateway's queued and completed messages. Default 30,000 ms |
| `txReceiptTimeout` | No | Wait for a transaction receipt. Default 30,000 ms |
| `mpcEventTimeout` | No | Wait for the on-chain `ProcessedMPC` event. Default 30,000 ms |

`client.address()` returns the address the client is operating as.

### Without a gateway

Omit `gatewayUrl` and the client sends every transaction — deposits, transfers, withdrawals
and vault operations, in both privacy modes — straight to the Merces contract from the
wallet, then waits for the `ProcessedMPC` event (bounded by `mpcEventTimeout`). The user pays
gas. This works on every deployment, but needs `token: 'ERC20'`: the constructor throws for
`'EIP3009'` without a gateway.
See [Gateway](/docs/finance-solutions/integrate/gateway).

## Register

An address must be registered before it can hold a balance:

```typescript
const index = await client.register();
```

This registers the public key of your `secretKey` against your address, returning your index
in the tree. If the address is already registered it returns the existing index. It throws
`RegisterError` if registration fails.

## Privacy modes

Every operation comes in two variants. Which you choose determines what the transaction
reveals and how fast it settles — see [Privacy model](/docs/finance-solutions/concepts/privacy-model)
for what each mode hides, from whom, and the throughput each sustains.

The method names predate the terminology on that page:

| Method prefix | Mode |
|---|---|
| `private*` | Private (default) |
| `confidential*` | Partial-private |

Graph-private transfers are not exposed by this client.

Pick per transaction — an account can use both.

## Deposit

Deposits move tokens from the public balance into the Merces balance. The amount is visible
onchain either way, since tokens are moving; the mode determines whether the crediting
account is hidden.

```typescript
import { parseUnits } from 'viem';

const decimals = await client.getDecimals();
const amount = parseUnits('100', decimals);

await client.confidentialDeposit(amount);
// or
await client.privateDeposit(amount);
```

`getSymbol()` and `getName()` are also available for token metadata.

## Balances

```typescript
const onchain = await client.getErc20Balance();   // public
const merces  = await client.getPrivateBalance(); // reconstructed from the node shares
const vault   = await client.getVaultBalance();   // vault shares
```

## Transfer

```typescript
await client.confidentialTransfer(RECEIVER_ADDRESS, amount);
// or
await client.privateTransfer(RECEIVER_ADDRESS, amount);
```

The receiver must already be registered. Transferring to your own address throws
`CannotTransferToSelfError`.

## Withdraw

```typescript
await client.confidentialWithdraw(amount);
// or
await client.privateWithdraw(amount);
```

A withdrawal ends in an ordinary token transfer, so its amount and destination are visible
onchain — but in private mode nothing links it to any particular transfer.

## Vault

The vault is an ERC-4626 yield vault. Deposits and withdrawals are private: the holder is
carried as a secret-shared identity reference, so positions are not attributable.

```typescript
await client.vaultDeposit(amount);
await client.vaultWithdraw(amount);

const shares = await client.convertToShares(assets);
const assets = await client.convertToAssets(shares);
```

`getVaultBalance()` returns your holding in shares; `convertToAssets` turns that into the
underlying token amount. See [Private yield](/docs/finance-solutions/private-defi/private-yield).

## Transaction history

Two functions, for two different jobs. Both are standalone imports rather than methods on
`Client`, and both take the ID registry and orchestrator URLs explicitly.

`getTxHistory` returns the account's own decrypted history:

```typescript
import { getTxHistory } from '@taceo/merces2-client';

const history = await getTxHistory(
  ID_REGISTRY_URL,
  ORCHESTRATOR_URL,
  client.address(),
);
```

`getTxList` returns a paginated list with a total count, for building a ledger view:

```typescript
import { getTxList } from '@taceo/merces2-client';

const { transactions, total } = await getTxList(
  ID_REGISTRY_URL,
  ORCHESTRATOR_URL,
  { page: 1, pageSize: 25 },
);
```

Both accept optional `startTime` and `endTime` bounds. Results are a tagged union across the
eight transaction kinds — private and confidential deposit, withdraw and transfer, plus
vault deposit and withdraw — so narrow before reading fields:

```typescript
for (const tx of history) {
  if ('PrivateTransfer' in tx) {
    console.log(tx.PrivateTransfer.amount, tx.PrivateTransfer.time_stamp);
  }
}
```

`getTxHistory` decrypts to plain values. `getTxList` returns entries where private fields
are still secret shares, so use it for counts and pagination rather than for reading
amounts.

## Errors

| Error | Means |
|---|---|
| `RegisterError` | Registration failed |
| `NotFoundError` | The address is not registered |
| `InvalidAmountError` | The amount is zero or negative |
| `InsufficientBalanceError` | Not enough balance for the operation |
| `CannotTransferToSelfError` | Sender and receiver are the same account |
| `ProofError` | Proof generation failed |
| `InvalidTransactionError` | The MPC network marked the transaction invalid |
| `NonCompliantError` | The gateway rejected the transaction in its compliance checks |
| `TimeoutError` | One of the configured timeouts elapsed |

```typescript
import { TimeoutError, InsufficientBalanceError } from '@taceo/merces2-client';

try {
  await client.privateTransfer(receiver, amount);
} catch (err) {
  if (err instanceof InsufficientBalanceError) {
    // ...
  } else if (err instanceof TimeoutError) {
    // may still have been processed — see below
  } else {
    throw err;
  }
}
```

A `TimeoutError` is not a failure signal. The transaction may still be processed — check the
balance or the history before retrying, or a double spend becomes possible.
